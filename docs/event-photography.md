These are representative photographs for development sample events, not documentation of actual EventNexus gatherings or endorsements by the people shown. Event Details labels them as illustrative. No AI-generated imagery is used.

Each event references its own local `/images/events/<key>.webp` asset in MongoDB. The corresponding `-640.webp` variant is selected through `srcset`; no random photo endpoint or external image hotlink is used at runtime. Main files are 1280 x 800, small files 640 x 400. The 60 WebP files total approximately 2.45 MB. Images were reviewed in a contact sheet and crops adjusted to keep subjects visible.

## Development seed update

From `server`, with the existing development-only safeguards enabled:

```powershell
$env:EVENTNEXUS_SEED_ALLOW = 'development-only'
$env:EVENTNEXUS_SEED_DB = 'eventnexus'
npm run seed:events:images
npm run seed:events:verify
```

`seed:events:images` requires the existing cohort. It validates ownership and registration consistency, then atomically updates only missing image fields. It preserves event IDs, timestamps, dates, titles, descriptions, capacity, counters, users and registration records. It compares core-data fingerprints before/after and rolls back if non-image data changes. Repeating it is a no-op. Existing custom photo URLs are retained. No cleanup/reseed is required or performed. Normal `seed:events` also associates photographs for new cohorts and attaches missing photos on repeat runs.

The optional `imageUrl` and `imageAlt` fields are accepted by event create/update validators. `imageUrl` accepts HTTPS or the local event-asset path pattern; blank clears it. An image-only PATCH no longer injects the create-time category default. Existing events without images retain the original artwork. Failed photo loads use the same fallback without changing the reserved photo dimensions.

## Asset maintenance

The checked-in WebP files are sufficient for the app, seed and tests; no image tooling is needed in production. To deliberately reacquire/recrop originals, run `npm run seed:events:download-photos`. This maintenance-only command needs network access and an existing Python/Pillow installation; no new npm/runtime dependency is added. It downloads only the curated Pexels originals into ignored `.cache/eventnexus-photo-sources`, then `prepare-photos.py` creates both variants using the explicit crop centers in `photos.json`. The application never runs this command.

The provenance manifest is `server/scripts/seed-events/photos.json`. Do not replace its verified page links with image-search thumbnails or random image services.
